      How it works

      • XO Engine (@xo-cash/engine) — opens one account per mnemonic on chipnet, connects to Electrum, and builds every transaction from a template. This app follows the official getting-started flow: Engine.create → importTemplate(p2pkhTemplate) → setDefaultPolicies → generateLockingBytecodeFromDefaultPolicy('receive') → invitation (sendSatoshis) → appendInvitation → addChangeToInvitation → signInvitation → executeAction({ broadcastTransaction: true }).
      • XO Template (@xo-cash/templates) — the p2pkhTemplate describes the pay-to-public-key-hash use case; the engine trusts the template, not the app, to decide what your keys sign.
      • XO Wallet — the throwaway chipnet wallet above is the XO account: its mnemonic never leaves this browser (localStorage, testnet only), and its receive address is the tip jar's address.
      • XO State / Utils (@xo-cash/state, @xo-cash/utils) — the engine's account storage and invitation helpers (serializeInvitation / deserializeInvitation).
      • libauth (@bitauth/libauth) — cashaddr ↔ locking-bytecode conversion and mnemonic generation.
      • No backend, no custody — a static page. A tip jar is just a URL (#/tip?id=…&name=…&target=…&to=…). The goal progress is the sum of recorded tips to that jar's address.
      • Different from BlazePay — BlazePay is private one-to-one payment links; TipJar is public tip pages with a funding goal, progress bar, and a public tip feed.
